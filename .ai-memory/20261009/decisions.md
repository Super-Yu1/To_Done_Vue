| D22 | 统计里的「未完成」= `total - done` | 不依赖后端 `todo` / `inProgress` 两个计数字段，后端按两态或三态统计都能得到正确结果 | 后端明确收敛两态并新增字段时可直接读取 |
| D23 | 删除随本次改造失效的死代码（`TASK_PRIORITY_WEIGHT`、`TASK_SORT_OPTIONS`、`TASK_STATUS_COLOR`、`--color-status-todo`、`--color-status-doing`） | 戒幽灵代码：改造后无人引用。代价是前端不再持有「优先级按业务权重排」的知识——该逻辑本就在后端 | 重新提供排序或状态色时按需恢复 |
| D24 | 顶栏主题按钮只切浅/深两态；「跟随系统」只在个人中心「外观」里选 | 用户 2026-10-10 要求。处于跟随时点按钮按眼前显示的反面切，避免"点了没反应"的错觉。与 8.7/8.8「顶栏一个按钮循环三态」冲突，须进位文档 | 用户要回循环三态：恢复 `cycleMode` 即可（`setMode` 与设置页不受影响） |
| D25 | 「外观」设置放进个人中心而非新建 /settings 页 | 项目已有个人中心承载账号与偏好（头像/资料/邮箱/密码），为一个三选一控件新开页面违反"功能能不加就不加"（4.1 极简优先）；8.2 路由表也没有 settings | 需要独立的设置页时再拆，`useTheme` 的 `setMode` 可直接复用 |
| D26 | 演示模式覆盖**前台全部**：任务 / 回收站 / 个人中心 / 主题；**不含后台** | 用户要求「演示模式需要展示系统的所有功能点」；8.6 明确「演示模式不含后台，顶栏也不给入口」，所以"全部"天然不含后台 | 要演示后台时：需先推翻 8.6 的隐私边界说明（后台只管账号） |
| D27 | 演示模式的写操作口径统一为「只提示不落数据」，任务状态切换是唯一例外 | 任务新建/编辑/删除（既定）与回收站恢复/彻底删除/清空（本轮补）都拦截；若"删除被拦而恢复能生效"会自相矛盾。状态切换例外是因为 8.6 交互行明列「可切换状态」 | 用户希望回收站操作也真实演示时：改成内存态（刷新还原），但需同时放宽任务删除，保持口径一致 |
| D28 | 个人中心与回收站抽成共享组件，真实页与演示页共用 | 8.6 要求「页面结构与本尊一致（同一套组件）」。代价是分区组件只负责收集与校验、动作由父级决定（多一层 emit）；收益是密码规则、字段、文案只维护一处 | 演示页将来要做完全不同的结构时，可拆出独立的演示组件 |
| D29 | `CaptchaField` / `EmailCodeField` 增加 `demo` 分支：本地生成验证码、跳过发信直接倒计时 | 演示模式不能请求后端（8.6），而验证码天然依赖后端；本地生成让「点图刷新 → 填码 → 获取邮箱码 → 倒计时」整条交互可体验。代价是这两个组件多了一个布尔分支 | 演示模式取消验证码展示需求时，删掉该分支即可 |
| D30 | 主题过渡用「切换期间临时挂 `.theme-transition`」而非常驻全站过渡，时长 800ms 由 `--dur-theme` 统管 | 用户要求缓慢切换且不闪动。常驻 800ms 全站过渡会把悬停手感拖垮（组件自身只有 150/200ms）；只给 `html` 加过渡又管不到子元素。临时接管窗口同时满足两者。JS 侧用 `getComputedStyle` 读该变量，避免毫秒数写两处 | 若将来所有组件都改用颜色变量且悬停也走 800ms 不违和，可去掉临时类改成常驻 |
| D31 | 任务行只显示标题 + 一行描述，不再渲染配图；整行即编辑入口，去掉铅笔按钮 | 用户 2026-10-10 要求。列表因此变成纯扫读视图，配图只保留在数据层（接口字段不动）。整行可点的代价：行是 `role="button"` 且内含勾选/删除两个按钮（嵌套交互元素的可访问性折中），用 `@click.stop` 隔离、并用 `window.getSelection()` 判断避免抢走划选复制 | 要回配图或独立编辑按钮时：把图片区与按钮加回 `TaskItem`，栅格恢复四段以上 |
| D32 | 弹窗开合动效走「覆盖 EP 的 `.dialog-fade-*` 时长 + 重定义关键帧」，而不是自建弹窗或 View Transitions | 用户要求点击卡片弹出浮窗有动画。EP 本就有一套（遮罩淡入 + 面板上浮），覆盖它成本最低且全局生效（含后台五个弹窗）；时长抽成 `--dur-dialog: 320ms`，用同名同形选择器靠加载顺序覆盖，减少动效偏好下归零 | 想要「从卡片位置长出来」的形变效果时：需按卡片与弹窗的 rect 计算 transform-origin，属另一套实现 |
| D33 | 圆角收敛为四档阶梯：sm 6 / md 12 / lg 20 / pill（胶囊），不再出现阶梯外数值 | 用户要求统一所有圆角含弹窗。四档而非单一值：极小件（14px 复选框、12px 骨架条）用 20px 会变成胶囊，角色不同的元素需要不同档位；阶梯把「谁用哪档」写进注释，比一个数值更可控。代价是 EP 里几处派生值（small 按钮 11px）需要单独压平 | 想要「所有圆角同一个值」时：把 md 与 lg 都指向同一个变量即可，但要接受输入框变胶囊的观感 |
| D34 | EP 圆角覆盖分两层：`:root` 只放 EP 在 `:root` 声明的变量（base/small/round）；EP 在组件元素上声明的（弹窗/确认框/分页/标签/浮层）必须写在同选择器上；EP 没给变量的（表格）直接补规则 | 实测发现元素上的直接声明会压过 `:root` 继承值——写在 `:root` 完全无效（`.el-dialog` 仍是 12px）。这是 EP 的实现细节，凭记忆写必然踩 | EP 升级后若把变量上移到 `:root`，两层可合并为一层（升级时重跑一遍逐元素实测即可发现） |
| D35 | 「先划掉、再下移」由**数据层延迟重排**实现（`changeStatus` 拆两步 + `sleep(readStrikeMs())`），而不是用 CSS 延迟 FLIP 位移 | 用 `transition-delay` 拖住 `.row-move` 会连带拖慢其他行的让位（删除、筛选也走同一类），范围不可控；把重排时点交给 `changeStatus`，影响面只限勾选这一条路径。代价：演示侧的可见列表要从 computed 改成显式 `rebuild()`（顺带与 store 同构） | 若将来所有列表变动都要统一节奏，可考虑把「重排时点」抽象到 TaskList 层统一调度 |
| D36 | 勾选动画时长以 `--dur-strike` 为唯一来源，JS 用 `readStrikeMs()` 读取 | 同一段节奏若在 CSS 与 JS 各写一份毫秒数，改一处忘一处就会错位；「减少动效」偏好下变量归零，JS 也随之不等待 | 无（该模式已用于 `--dur-theme`，验证有效） |
| D37 | 优先级只有低 / 中 / 高三档，去掉「紧急」 | 用户 2026-10-10 要求。连带删除 `--color-priority-urgent` 色值与演示数据里的 4 条紧急（2→高、2→中）。后端 `task.priority` 是无 CHECK 的 VARCHAR，收敛枚举不必动 DDL，但要同步后端枚举 | 要回四档时：`TaskPriority` 与优先级字典加回 `URGENT`，并补回色值 |
| D38 | 演示模式的写操作**全部放开为内存态**：新建 / 编辑 / 删除 / 切状态 / 回收站恢复·彻底删除·清空都真的生效，刷新还原；个人中心的资料·邮箱·密码仍只提示不保存 | 用户先问「可否也实现删除」。只放开删除会出现「能删不能建」的不对称，比原先「全部拦截」更让人困惑；用户此前也明确过演示要展示全部功能点。个人中心例外是因为演示模式没有账号身份，且页面文案已声明改动不保存 | 要回到「全部拦截」：去掉 `create/update/remove` 与 `useDemoTrash`，页面改回统一提示即可 |
| D39 | 演示任务与回收站共用 `mock/demoState.ts` 的模块级 ref（而非 Pinia） | 两个页面必须看到同一份内存数据才能闭环（删除→回收站→恢复）；但不该把演示分支塞进真实链路的 store，也不需要和真实数据并列出现在 devtools | 演示状态变复杂（多用户/多集合）时再考虑独立 store |
