# 后端修改说明（前端联调发现的问题）

> 只列**问题**——需要后端改或确认的事。已修复的条目不保留。
> 时间 = 前端发现该问题的时刻（本地时间）。联调环境：后端 8081，前端 `http://localhost:5173`。

1. **2026-10-18 01:12** · `GET /api/tasks` 的 `sortBy` 需要支持 **`completedAt`（完成时间）**。
   依据：设计说明书只列了 `recordedAt / dueDate / priority` 三个可排序字段，而前端排序下拉按需求已有「完成时间」一项（默认字段是 `dueDate`）。
   现状：前端会发 `sortBy=completedAt&sortDirection=asc|desc`；若白名单里没有它，大概率返回 400 或忽略该参数（未登录无法实测）。
   期望：把 `completedAt` 加进排序字段白名单。

2. **2026-10-18 01:12** · 排序需要保证两条稳定规则：**同优先级按截止时间**、**没有截止时间的一律排最后**。
   依据：需求定稿 —— ① 以优先级排序时，同优先级内仍按截止时间近 → 远；② 任何排序下，`dueDate` 为空的任务都排在最后（正序倒序都一样）。
   现状：前端已去掉本地重排、完全以服务端返回顺序为准，所以这两条只能由后端保证；SQL 层大致是 `ORDER BY priority DESC, due_date IS NULL, due_date ASC`（空值排最后这一句与方向无关）。
   期望：确认这两条已实现；若 `sortBy=priority` 目前只按单字段排，请补上截止时间作为次键。
