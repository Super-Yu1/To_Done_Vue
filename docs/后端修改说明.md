> 时间 = 前端发现该问题的时刻（本地时间）。联调环境：后端 8081，前端 `http://localhost:5173`。

本轮 1 条（2026-11-01 00:02，后台入口安全排查）：

## 1. 【建议·安全】公网部署时，后台真正的暴露面在 Swagger 与登录接口，不在 `/admin` 路径

- **先把口径说清**：前端 `/admin` 只是 SPA 路由 —— 没 token 会被守卫送去 `/admin/login`，
  几个页面在接口层面全靠 `SecurityConfig` 的 `hasRole("ADMIN")`（用户 token 连签名都验不过），
  所以「猜到 `/admin`」本身拿不到任何数据。能被打的是下面几处。
- **现状（`config/SecurityConfig.java` 的 `WHITELIST`）**：`/swagger-ui.html`、`/swagger-ui/**`、
  `/v3/api-docs/**`、`/actuator/health` 对外放行。前两者等于把**后台全部接口、入参、错误码**
  （1009 / 5001 / 5002 …）公开给任何访问者 —— 扫描器不用猜路径，直接读文档。
- **要改**：
  1. 生产 profile 关掉 springdoc（`springdoc.api-docs.enabled=false` + `springdoc.swagger-ui.enabled=false`），
     或只在内网 / 本地开；至少别让它和后台接口一起在公网可读。
  2. `/api/admin/auth/login` 加 **per-IP 限流**（例如 1 分钟 5 次）+ 连续失败计数（锁 IP 或加退避）；
     现在只有「每次都要图形码」这一道，对自动化不算硬门槛。
  3. `/api/admin/**` 在网关（nginx）层做来源限制（内网 / 白名单 IP）—— 这条只对齐口径，实际不在应用里做。
- **为什么**：前端能做的只是「不让人看见入口 + 不索引」（已完成，见 `docs/前端修改说明.md` 第 3 条），
  挡不住直接打接口；而 Swagger 是目前唯一**公开可读的后台元信息**，性价比最高的一刀先切这里。
