## 2026-10-28 00:47 · 登录接口的图形码改成「连续错 2 次密码后，第 3 次起才要求」

**为什么**：现在每次登录都强制图形码，每天正常登录也要先看一张图。新规则：同一账号**连续输错 2 次密码**，
从第 3 次尝试起才要求图形码；登录成功即清零。前端已按新契约改完（`src/views/LoginView.vue`、
`src/utils/loginAttempts.ts`、`src/types/index.ts`），**两边必须一起发** —— 后端不改的话，前两次不带
`captchaId` / `captchaCode` 会被参数校验拦成 400。

**前端现在这样调** `POST /api/auth/login`

| 场景 | 请求体 |
| --- | --- |
| 没有连续失败（第 1、2 次尝试） | `{ "email": "...", "password": "..." }` |
| 第 3 次起 | `{ "email": "...", "password": "...", "captchaId": "...", "captchaCode": "..." }` |

**需要后端做三件事**

1. `captchaId` / `captchaCode` 从必填改为**条件必填**（Swagger 注解同步，不要标 required）。
2. 维护「连续密码错误次数」：Redis `INCR todone:login:fail:{email}` + `EXPIRE 1800`（30 分钟，与前端窗口一致）。
   - 只有**密码比对失败**才 +1；登录成功 `DEL` 计数。
   - 冻结（1006）/ 已注销（1007）**不计数** —— 它们仍在密码通过之后判定，是账号状态问题，不是密码错。
   - 按**邮箱**计数（含不存在的邮箱），避免拿不存在的账号探测时绕过闸门；同一邮箱跨设备共用一份计数。
   - Redis 不可用时降级为「不强制图形码」，不要让登录整体 503。
3. 新增业务码 **4008 · 请先输入图形验证码后重试**（HTTP 200、`data: null`）：
   「该要图形码了，但请求没带」时返回它。前端收到 4008 会自动把图形码弹窗打开
   （换浏览器 / 清缓存导致本地计数没跟上的情况，用户不至于卡在「只报错、看不到要输码」）。

**判定顺序（建议）**

1. 读计数 `n`（键不存在即 0）；
2. `n >= 2` 且没带 `captchaId` / `captchaCode` → **4008**（不校验密码、不计次数）；
3. `n >= 2` 且带了 → 先校验图形码：错 / 过期 / 已用 → **4001**，**不计入密码错误次数**；
4. `n < 2` 但请求带了图形码 → 照常校验（错仍返回 4001），不要静默忽略；
5. 校验密码：失败 → **1003** 且计数 +1；成功 → `DEL` 计数并签发 token；
6. 冻结 / 注销的判断保持在密码通过之后。

**验收用例**

| 场景 | 期望 |
| --- | --- |
| 干净状态第 1 次就输错密码 | 1003，不需要图形码 |
| 连错 2 次后，第 3 次不带图形码 | 4008 |
| 第 3 次带错图形码 | 4001；登录页弹窗留驻并换图，密码错误次数不变 |
| 第 3 次图形码对、密码错 | 1003；第 4 次仍要图形码 |
| 第 3 次全部正确 | 登录成功，计数清零，之后再登录又不需要图形码 |
| 错 2 次后 30 分钟无操作 | 计数过期，回到「不需要图形码」 |
| 冻结 / 注销账号 | 1006 / 1007，且不增加计数 |

**这次没改的部分**：`POST /api/admin/auth/login` 仍每次都要图形码（后台是高权限入口，前端没动）；
注册、找回密码、发邮箱验证码的图形码规则也不变。
