## 1. 【功能】`AdminUserVO` 需要返回 `lastLoginAt`（上次登录时间）

- **前端现状**：`/admin/users` 已加上「上次登录时间」列（`src/components/admin/AdminUserTable.vue`），
  字段按 `AdminUser.lastLoginAt` 读，**后端没返回就显示「—」** —— 后端补上即自动出现，前端不用再改。
- **要什么**：列表（#26）与详情（#27）都返回 `lastLoginAt`：时间字符串（与 `createdAt` 同格式），
  从未登录 / 没有记录时为 `null`。**列表与详情必须一致**（前端是同一个类型 `AdminUser`）。
- **为什么现在没有**：`app_user` 表没有登录时间列（`admin_user` 有 `last_login_at`，用户侧一直没建）；
  `login_audit` 只有 2026-10-31 之后的记录，不能当历史口径用。
- **推荐做法（与 `admin_user` 同一口径）**：
  1. `app_user` 加一列 `last_login_at TIMESTAMP`，`sql/todone.sql` 的建表语句与 COMMENT 同步
     （已有库补一条 `ALTER TABLE app_user ADD COLUMN last_login_at TIMESTAMP;`）；
  2. `UserService.login` 的**成功分支**写当前时间（与失败计数归零同一处；密码错等失败一律不动它）；
  3. `AdminUserVO` 加 `LocalDateTime lastLoginAt`，`AdminService.toVO` 多传一个 `user.getLastLoginAt()`。
- **备选（不改表）**：用 `login_audit` 聚合 —— 整页一次查询，`actor_type='USER' AND result='SUCCESS'`
  按 `actor_id` 分组取 `MAX(created_at)`；代价是 2026-10-31 之前的登录永远查不到，老账号会一直显示「—」。
- **注意**：
  - `AdminUserVO` 是 record，加参数要同步改 `AdminService.toVO` 的构造调用，以及按字段断言该 VO 的测试（`AdminFlowTest`）；
  - 加字段方案**先执行 DDL 再重启**，否则 `User` 实体映射会报列不存在；
  - 前端只读这个字段，**不参与筛选与排序**，不用加查询参数。
