1. **2026-10-13 22:47** · 后台接口 `/api/admin/**` 仍未提供。
   范围：Swagger 里没有管理员登录、用户列表、冻结 / 解冻 / 注销、改资料、重置密码、新增管理员这些接口
   （2026-10-13 16:00 复核：现有 16 条路径中 **0** 条以 `/api/admin` 开头）。
   影响：前端 `/admin/login`、`/admin/users`、`/admin/admins` 三页只能停在骨架态（请求会 404），无法联调。
   期望：P5 完成后告我一声，我接上并验「登录 → 列表筛选分页 → 冻结 / 解冻 / 注销 / 重置密码 / 新增管理员」。

2. **2026-10-13 16:00** · 任务新建 / 更新的 Swagger 请求体只声明 `application/json`，**看不出配图怎么传**。
   实测：前端 `POST /api/tasks` 发的是 multipart —— `data` 段（`application/json` 的任务 JSON）+ `images` 段（0~9 个文件），
   服务端正常落库并返回预签名直链（一次新建 2 张图成功，含压缩后的 JPEG 与 GIF）；`PUT /api/tasks/{id}` 同样可用。
   但 `/v3/api-docs` 里 `POST /api/tasks` 的 `requestBody.content` 只有 `application/json`。
   影响：联调者照文档会以为配图不能随任务提交，或不知道 part 名与段的对应关系，容易白折腾一轮。
   期望：把这两个接口声明成 `multipart/form-data`：`data` 标 `application/json`、`images` 标二进制数组并写明最多 9 张。

3. **2026-10-13 16:00** · `TaskCreateRequest` 缺 `imageOrder`（`TaskUpdateRequest` 里有）。
   详情：更新时前端用 `imageOrder` 表达配图顺序（已有图给 id、新图占位 `'NEW'`、空数组 = 删光配图），
   文档里有、行为也对得上；新建时前端按同一约定传 `['NEW', ...]`，接口不报错且两张图都落库，
   但**这个字段不在 `TaskCreateRequest` 里** —— 顺序是否真按 `imageOrder` 生效无从确认（也可能是按 part 顺序）。
   期望：`TaskCreateRequest` 补 `imageOrder`；若新建只认 part 顺序，请在文档里写明，我把前端多余的字段去掉。
