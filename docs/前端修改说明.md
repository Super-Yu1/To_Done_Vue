> **接口签名与请求 / 响应字段一律以 Swagger 为准**（`http://localhost:8081/swagger-ui.html`，JSON 在 `/v3/api-docs`），这里**不重复**字段表。

## 1. 环境与启动

- **后端地址**：`http://localhost:8081`（端口取 `application.yaml` 的 `server.port`，当前是 8081；不要连 8080）。
- **前端 dev server**：`http://localhost:5173` —— 已在后端 CORS 白名单里；**换端口要后端加白名单**，否则预检直接 403。
- **后端怎么起**：IDE 直接 Run 即可（开发配置用 `spring.config.import` 直读 `.env.development`，没有启动脚本了）；连的是远程三实例（PG / Redis / MinIO）。
- **生产**：`/api` 由 Nginx 反代；图片直链挂在 MinIO 的对外域名上——**不要在前端拼 `/media`**，那条路已作废。

## 2. 认证与登录态

- 登录 / 注册成功后把 `token` 存下来（推荐 `localStorage`，注意 XSS 面；后端走的是 `Authorization: Bearer`，不是 Cookie）。
- 受保护请求统一加 `Authorization: Bearer {token}`。
- **统一 401 处理**：清掉本地 token → 跳登录页。401 有四种来源：没带/带错 token、**token 过期（1440 分钟）**、**改密后**旧 token 失效、**换邮箱后**旧 token 失效（后两条见第 4 节）。
- **改密 / 换邮箱成功之后要引导用户重新登录**——后端会在成功那一刻让该账号的旧 token 全部失效（2026-10-13 口径）。
- 登录**只认邮箱**（用户名不能登录）；被冻结（1006）与已注销（1007）都在密码校验**通过之后**才给出；已注销账号来登录一律是 **1003**（和「邮箱不存在」同一个码，别在前端区分）。

## 3. 验证码怎么用（这是流程，不是字段表）

1. 进注册 / 登录 / 找回密码页 → 先调 `GET /api/verify/captcha` 拿 `captchaId` + `image`（Base64，直接拼 `data:image/png;base64,` 放 `<img>`）。
2. 提交时带上 `captchaId` + `captchaCode`。
3. **图形码是一次机会**：任何一次提交（哪怕后面因为邮箱码错失败）它都被消费掉了 → **提交失败后必须重新拉一张图形码**（这是最常见的联调错觉来源）。
4. 图形码大小写不敏感；有效期 120 秒。
5. 发邮箱验证码有 **60 秒冷却**（再点就是 4003）与 **每日 10 次上限**（4004）；**倒计时请用响应里的 `resendAfterSeconds` / `expiresInSeconds`，不要写死**。
6. 「找回密码」**邮箱不存在也返回成功**（防枚举）→ 前端无论真假都提示「验证码已发送」。
7. 开发环境**真发邮件**（Resend），测试时请用你收得到的邮箱。

## 4. 图片（头像与任务配图）

- **上传前前端先处理**：头像弹 1:1 取景框 → 裁 512×512；通用图长边 >1920 或体积 >1MB 时用 canvas 重绘（质量 0.85），**GIF 跳过压缩**。后端不做任何图像处理。
- **上传字段名固定 `file`**（multipart）；超过 10MB 会被 413 + 3002 拦，格式不对是 3003（后端还会验**文件头魔数**，改扩展名没用）。
- **`avatarUrl` / `images[].url` 是 30 分钟有效的预签名直链**：不要落库、不要长期缓存；过期表现为 403/404，**重新调接口拿新 URL** 即可（列表刷新就会换新）。
- 换头像后**旧 URL 立即失效**（后端已删旧对象）——别把旧 URL 留在前端缓存里。
- 展示时 `<img src={url}>` 直接可用，**不需要带 token**（签名在 URL 里）。

## 5. 统一响应与错误处理

- 成功与业务失败**都是 HTTP 200**，看 `code`。建议在 axios 拦截器里统一分流：`code === 200` 取 `data`，否则提示 `message`（后端文案已是用户可读中文）。
- 非 200 的只有这几类：**400** 参数/格式不符、**401** 登录失效、**403** 权限或来源不允许、**405** 方法不对、**413** 文件过大、**503** 验证码服务降级（`code=4007`，提示「稍后重试」即可）。
- 时间格式统一 `yyyy-MM-dd'T'HH:mm:ss`（本地时间，无时区后缀）；直接按字符串解析即可。
- 分页响应字段：`records / total / page / size / totalPages`。

## 6. 分页与查询约定

- `page` 从 **1** 开始；`size` 上限 **100**，越界（0、负数、>100）**返回 400**（后端故意不静默截断，前端别送非法值）。
- 任务列表排序白名单：`recordedAt` / `dueDate` / `priority`；**`priority` 按业务权重排**（低 → 中 → 高 → 紧急），不是字典序。

## 7. 联调时最容易踩的四个坑（都验证过）

| 坑 | 现象 | 正解 |
| --- | --- | --- |
| 拿着用过的图形码重试 | 一直 4001 | 每次提交失败都重新拉图形码 |
| 把 `avatarUrl` 缓存起来 | 过一会儿图片 403/404 | 用时重新调接口，URL 只有 30 分钟 |
| 换端口起前端 | 预检 403 | 让后端把新来源加进 `app.cors.allowed-origins` |
| 改完密码继续用旧 token | 突然全是 401 | 后端已踢下线，引导重新登录（换邮箱同理） |
