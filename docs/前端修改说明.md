## 3. 2026-11-01 00:02 · 【待办·部署】后台入口 `/admin` 太容易被猜 / 扫描出来 → 用 nginx 隔离

- **要做什么**：生产部署时用 nginx 把后台收进白名单（配置见下）。做完后：公网访客访问 `/admin` 与 `/api/admin` 一律 403，
  只有白名单 IP（先过 Basic Auth）能进；路径猜不猜得到已无所谓。
- **为什么**：`/admin` 是 SPA 路由，猜到了也只是登录页，拿不到数据（接口全靠后端 `hasRole("ADMIN")`）；
  但路径一扫就暴露「这站有后台」。⚠ 前端能做的只有降噪（token 严格化 + `noindex` 已完成）；
  **bundle 是公开的，靠改路径藏不住**，隔离只能发生在 nginx。
- **为什么 `/api/admin` 不用 Basic Auth**：前端 axios 会带 `Authorization: Bearer <token>`，
  nginx 的 `auth_basic` 也用 `Authorization` 头 —— 两者冲突，浏览器补发的 Basic 凭据会顶掉 Bearer，接口全 401。
  所以约定：**UI 路径（`/admin`）用 Basic Auth，API 路径（`/api/admin`）只做 IP 白名单**。

### nginx 配置（整段可抄，改三处：域名、白名单 IP、后台口令文件）

```nginx
# /etc/nginx/sites-available/todone
# 拓扑：浏览器 → nginx(443) ─┬─ 静态文件（dist，SPA 路由回退 index.html）
#                            └─ /api/** → 127.0.0.1:8081（Spring Boot）

# 后台口令文件（只做一次；-c 只在首次创建时带）：
#   sudo htpasswd -c /etc/nginx/.htpasswd_admin 你的用户名
# 不装 htpasswd 的话：openssl passwd -apr1 生成一行「用户名:密文」自己贴进文件

server {
    listen 80;
    server_name todone.example.com;          # ① 改成你的域名
    return 301 https://$host$request_uri;    # 全部压到 https
}

server {
    listen 443 ssl;
    http2 on;
    server_name todone.example.com;          # ① 同上

    ssl_certificate     /etc/letsencrypt/live/todone.example.com/fullchain.pem;  # ② certbot 申请
    ssl_certificate_key /etc/letsencrypt/live/todone.example.com/privkey.pem;

    root /var/www/todone/dist;               # ③ npm run build 产出的目录
    index index.html;

    # 上传上限必须 ≥ 图片上限（10MB）+ 表单开销，否则配图上传会在 nginx 这里 413，
    # 后端那道 3002/10MB 校验根本轮不到跑
    client_max_body_size 12m;

    # ---------- 后台 UI：Basic Auth + IP 白名单（satisfy all = 两关都要过） ----------
    # 只拦页面，不拦 XHR —— 所以和 Bearer 头不冲突
    location /admin {
        auth_basic           "Admin";
        auth_basic_user_file /etc/nginx/.htpasswd_admin;
        allow 203.0.113.7;               # ④ 你的固定 IP；家宽 IP 会变，见下方「IP 会变怎么办」
        allow 10.0.0.0/8;                # 内网段按需加
        deny  all;
        satisfy all;
        try_files $uri /index.html;      # /admin、/admin/users 都是前端路由，回 index.html
    }

    # ---------- 后台 API：只做 IP 白名单（不能用 auth_basic，见上） ----------
    location /api/admin/ {
        allow 203.0.113.7;               # ④ 与上面保持一致
        allow 10.0.0.0/8;
        deny  all;
        proxy_pass http://127.0.0.1:8081;
        include /etc/nginx/proxy_params; # Debian/Ubuntu 自带；等价于下面四行 proxy_set_header
    }

    # ---------- 前台 API：任何人可访问（token 在请求头里，边界在后端） ----------
    location /api/ {
        proxy_pass http://127.0.0.1:8081;
        # ClientIps 取 X-Forwarded-For 的第一跳做登录审计：这里必须把真实客户端 IP 递过去。
        # 用 $remote_addr（而不是 $proxy_add_x_forwarded_for）：别信任客户端自带的 XFF，可伪造。
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header X-Real-IP      $remote_addr;
        proxy_set_header Host           $host;
        proxy_set_header Authorization  $http_authorization;
    }

    # ---------- SPA：history 路由回退 + 静态资源长缓存 ----------
    location / {
        try_files $uri $uri/ /index.html;
    }
    location /assets/ {                  # vite 指纹文件，内容永不变
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    # ---------- 兜底：生产后端已关 Swagger，这里再拦一层（后端没关也能挡住） ----------
    location ~ ^/(swagger-ui|v3/api-docs) {
        return 404;
    }
}
```

> `include /etc/nginx/proxy_params` 不存在的发行版，把这一行换成：
> ```nginx
> proxy_set_header Host              $host;
> proxy_set_header X-Real-IP         $remote_addr;
> proxy_set_header X-Forwarded-For   $remote_addr;
> proxy_set_header X-Forwarded-Proto $scheme;
> ```

### 上线步骤（照顺序敲）

```bash

sudo nginx -t                                            # 语法检查，必须 OK 才往下

sudo certbot --nginx -d todone.example.com               # 已有证书就跳过
```

### 两个会踩的坑

- **家宽 IP 会变**：`allow` 里填运营商家宽 IP，隔几天就失效（自己被 403）。三条路任选：
  用 DDNS + `geo`/`map` 模块按域名放行；换 Tailscale/WireGuard，`allow 100.64.0.0/10`；
  或者干脆只留 Basic Auth（把 `allow/deny` 删掉、`satisfy all` 改 `satisfy any`）—— 弱一点，但不用维护 IP。
- **`/api/admin` 别加 `auth_basic`**：浏览器会把 `Authorization` 顶成 `Basic …`，前端的 Bearer 直接失效。
  同理，Basic Auth 只保护 `/admin` 这个前缀，不要图省事写成 `location /`。
